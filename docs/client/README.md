## How to read this package

Every feature described in these documents was verified directly in the LaraLMS source code (frontend, backend, and database models) at the time of writing. Where something was planned but is not built, it is marked **Not Included**. Where something works but with a gap, it is marked **Partially Implemented**. Where the audit could not fully confirm behavior without live testing against a running production database/browser, it is marked **Requires Verification**.

## Changelog

- **v1.6** — Student Performance Analytics (Document 13): `/analytics` (Admin) and `/director/analytics` (own batches only) with server-side filters (session → course → batch, subject, exam, dates, attendance range, status, search), summary cards, exam/subject/attendance/batch/trend charts, explainable at-risk reasons (never on a single mark), student drill-down, Excel/print export; thresholds in Settings → ফলাফল; every Student Portal page redesigned (grouped nav, results & marksheet, attendance calendar, fees, materials, videos, notices, profile with unsaved-changes guard) and the dashboard now uses the marksheet's own calculation; print output HTML-escaped.
- **v1.5** — UI modernization (Document 12): premium blue theme; public homepage login portal with three portal buttons; dedicated `/studentLogin`, `/staffLogin`, `/adminLogin` routes (old `/login` redirects) reusing the existing auth, with validation, loading/error states, safe `?next=` return and role-based redirects; Admin login now refuses student/staff accounts (optional `portal` field, 403 + audit); Student Dashboard redesign on real data; Staff Management redesign (overview, recent changes, search/filters, profile drawer, activate/deactivate, delete confirmation, Super Admin password reset); Smart Settings (categories, search, permission-aware, `?section=` URL, unsaved-changes guard, cancel, validation).
- **v1.4** — Mess workflow update (Document 10): monthly bills are **seat rent only**, generated by the server on the billing day (default the 1st, Asia/Dhaka) with a Vercel Cron route and once-per-month claims; admission takes a **one-time dining charge** and a **one-month advance** (held until check-out) on a single receipt — neither is ever in a monthly bill; configurable joining-month rent rule; **Super Admin permanent delete** of any Mess record (typed confirmation + audit log); joining-date correction with impact preview, optional bill re-issue, history and audit (new `mess:members:edit-dates` permission); per-Mess billing defaults; Mess SMS (payment, bill, due reminder, admission, check-out) with templates, duplicate prevention, test SMS and history; Mess Dashboard quick actions, previous due, auto-billing status, SMS alerts, recent admissions/check-outs; previous-due, month-wise and SMS reports; complaint resolution notes and maintenance cost; Student Portal bill details.
- **v1.3** — UI/UX modernization (Document 11): new design system (neutral + deep-orange palette, refined tables/forms/dialogs/tabs), grouped role-aware sidebar, header breadcrumb, working Ctrl+K global search, a permission-aware Main Dashboard "command center" backed by a new `/dashboard/overview` aggregation (date-range/course/batch filters, financial/student/attendance/academic analytics, real audit-log activity feed, quick actions) with a Mess Management overview and shortcut; refreshed Batch Director, Student and Mess dashboards; dashboard dates now use the institution timezone.

- **v1.2** — Added **Mess / Hostel Management** (Document 10): multi-Mess setup, rooms and seats, membership lifecycle for existing students, reservations, idempotent monthly billing, Mess payments kept separate from Course Fee collections, security deposit and final settlement, Mess expenses, complaints/maintenance, Mess notices, a Student Portal Mess page, Mess reports and Mess Settings. New Mess staff types (Mess Manager / Accountant / Caretaker) log in through the existing Staff Portal and see only their assigned Mess. Meal Management is **not** included. 🔵 Database-backed flows still require live verification on a test database (Document 10 §10.13).

- **v1.1** — Added: self-service **Change Password** (Topbar user menu) and a forced password-change screen shown when the backend flags an account as `mustChangePassword` (previously this flag existed but nothing in the app acted on it — the default seeded Super Admin password could not be rotated through the UI). See §3.5 and §8.
- **v1.0** — Initial handover package.
